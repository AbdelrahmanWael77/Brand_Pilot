## Key Learnings
- 2026-11-17: FLUX schnell (server/imageAi.js) obeys what comes FIRST in the prompt. Rules first ("no text…") gave flat 2D, orange clothing and a busy sky; putting the series' own illustration treatment and the subject first, then colours as words, then composition, then the wordless rule gave polished 3D in the brand palette with an empty headline area (server/series.js `buildIllustrationPrompt`). Leave skin tones out of the palette words (the vision read lists them).
- 2026-11-17: the owner's server-wide selected model can be a text-only OpenRouter free model ("No endpoints found that support image input"). Anything that sends pictures must not depend on the selection: `ai.complete({ use })` runs one request on another configured option; the series style read tries the selected one, then Anthropic / OpenAI, then the rest.
- 2026-11-15: `htmlToText` (public/index.html) keeps the text of `<title>`. A page built by scripts therefore looks non-empty; when deciding whether a fetched page has readable text, remove `<head>` / `<title>` first (see `siteAdd`).
- 2026-11-15: progress and "busy" flags of background work belong in `SRV` (memory), never in `S.ui` (saved with the state): a reload in the middle would leave the flag set for good.

## Do-Not-Repeat
- 2026-11-16: objects returned from code run in `node:vm` have the sandbox's prototypes, so `assert.deepEqual` / `deepStrictEqual` fails on equal-looking arrays ("same structure but not reference-equal"). Pass them through `JSON.parse(JSON.stringify(x))` first (done in `test/compare.test.js` and `server/channels.js`).
- 2026-11-15: patching `public/index.html` from `node -e "..."` in the shell loses backslashes in regexes (`\\w` arrived as `w`). Write the patch as a script file and use `String.raw` for code that holds a regex.
- 2026-11-15: do not judge "is this a grey?" by HSL saturation — it calls very light and very dark tints saturated (`#E2E8F0` scored 0.32). `colorRole` in server/brand.js uses chroma (max - min of the channels) plus lightness cut-offs.
- 2026-11-15: when several reads run in parallel, collect their failures from the results in input order, not at the moment each one fails — otherwise the order of the notes changes from run to run (a test in brand.test.js caught this).

## Decision Log
- 2026-11-17 (18, owner approved): the AI Director is saved conversations (chat list, follow-ups). Follow-ups send earlier turns as <history> that is context only, never a source — every claim still cites ids from <context>. Free models put ids inline in answers; stripIds removes them server-side.
- 2026-11-17 (17c, owner, repeated after 17a): Performance shows NO content recommendations at all — "What to post next" lives only in AI Content Series. Performance = measuring; series = deciding what to post.
- 2026-11-17 (17a, owner): Performance does not list series any more (no "Your series" panel) — series live only in AI Content Series. Topic recommendations belong inside the opened series (recommended topic, own list, AI ideas), not only on Performance.
- 2026-11-17 (17, owner brief "AI Content Series rebuild"): series posts are made in their own workspace (nav "AI Content Series"), never in Campaign Studio's generic banner. The finished post is composed in the browser (public/series.js `draw`): series background, the AI illustration feathered into it, the company's own logo file, approved text as real type — so wording edits never need a new picture and the logo is never redrawn. Creative references (library items with `ref`) are style examples only and never become facts. Why: the owner's main complaint was "an image inserted into a generic blue banner"; Canva AI credits were exhausted, so Canva cannot be the only path.
- 2026-11-16 (15b analytics ranking, first called 12b; owner): the comparison never shows a winner alone. "★ Best eligible" (not "best") marks the leader among channels that meet the minimum data; when another channel has a better observed value, it is marked "▲ Highest observed" with its exact unmet minimum ("reach 600 of 1,000 needed") in the cell, in a "Why:" line under the row, in the winner's finding card, and in the AI Director context. Minimums are presented as BrandPilot rules, never as confidence or statistical significance. Why: the owner saw Facebook 3.68 % "★ best" next to Instagram 15.9 % "small sample" and found it confusing although the math was right.
- 2026-11-16 (15 analytics comparison, first called 12): channel comparison never credits a result to a platform the data does not name. Leads go to a channel only by the CRM `source` text (`leadCol`); "Google" stays unassigned (organic or ads); organic-search leads are null, not 0, until some source names it; GA4 "Organic/Paid Social" stays one pooled number. The math lives once, in `public/compare.js`, and the server runs that same file in `node:vm` (`server/channels.js`) so the screen and the AI Director cannot drift apart. Why: the owner's brief forbids invented metrics and assumed attribution, and the real AI answered "cannot verify" until it got the same numbers.
- 2026-11-15 (9.8): other content types (CSS, images) are a per-read option of the guarded reader that only server code can pass; the `fetch-url` route never forwards options from the request body. Why: the browser must not be able to turn the reader into a general download proxy.
- 2026-11-15 (9.7): the website page chooser never fails the request because of the model: any model failure, unusable answer or answer with no listed page falls back to the keyword rule and says `chosenBy: 'rules'`. Why: the scan must work the same with the AI off. Same site = same host with a leading `www.` ignored and the same port; subdomains are other sites. Every page is still read by the guarded reader, one `fetch-url` per page, so the SSRF rules are untouched.
- 2026-11-15 (9.23–9.25, owner): which logo version goes on which background is decided by measuring the logo (canvas luminance of its visible pixels, contrast against the background with the Brand QA formula), never by the website's class names ("logo-dark" means a dark logo on some sites and a logo for dark backgrounds on others) and never by a model call. Why: the result must be the same on every run and work with the AI off; the user can override per version. Finding the logo on the website is rule-based too (`server/brand.js`), so there is no prompt to tune there.

- 2026-11-15 (10.4c, owner): Canva generation goes through Canva's remote MCP server from BrandPilot's own server, with each user's own Canva sign-in (connection key = company + user; records are per user and never shown to another user — Canva's MCP usage policy forbids reusing one user's context for another). Tool input schemas are discovered per user with `tools/list` and never hard-coded; the company logo is uploaded as a file and never described to the generator; a generated picture is asked without text or logo. Why: the schemas were not readable without a sign-in when this was built, and an invented logo was the failure seen in the 2026-11-15 trial.
- 2026-11-16: owner asked for a complete visual redesign (a pasted brief written for another app: it mentions Flutter, WhatsApp, green, an admin console — none exist in BrandPilot; apply its intent to the real screens). Chosen direction "Ledger" (paper/ink/vermilion, Fraunces + IBM Plex) on branch `redesign/new-product-identity`; it overrides AGENTS.md "avoid UI redesigns" for that branch only, and stays off `dev` until the owner approves. Vermilion (`--signal`) means current/next only — never a status or a data emphasis.
- 2026-11-16: the app sends headers that forbid framing, so a phone width cannot be checked in an iframe; force the `max-width` media rules on through CSSOM and set `body{width:390px}` instead.
